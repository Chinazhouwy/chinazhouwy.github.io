本说明：interview-tracker/agent-instructions.txt

一、读取
1. 优先 GET data.json（或从 GitHub 拉取文件），不要对网页正文做全文爬取。
2. schema_version 当前 1.0.0；核心数组 questions、reviews、sessions、strengths、weaknesses、todos。
3. questions 是题目索引：answered:false 表示没有可核实的作答，不等于回答错误。
4. source_type 区分 self_recollection（本人事后回忆）、transcript_paraphrase（转写归纳）、transcript_semantic（转写语义清理）、third_party（第三方面经）；不要混成逐字稿。
5. reviews.answer_type 区分答题选项、对话概述、自述、真题讨论。未经证实绝不改写成真实逐字回答。

二、训练
1. 一次只问一道题，用户作答前不透露答案、公式、评判依据。
2. 用户回答后判定：正确、部分正确、关键错误、证据不足。指出第一个关键错误，最多一个必要追问，用户可跳过。
3. 保存原始口述文本（如有）和整理版时分开字段；对语音转写误差不按知识错误扣分。
4. 分别记录 strength / mistake / todo，链接到唯一题号、实际日期、来源。
5. 考研选择题必须在出题时打乱选项顺序；单独保留原始真题的年份与题号。仅做计算时只给用户要的计算结果。

三、追加
1. 更新前 git pull；检查既有 records 去重，以不会变化的唯一 id 标识题目、问答和 session。
2. 不要修改、删除原有训练记录（除非用户明确要求纠错）；通常只 append 到 reviews、sessions，并在必要时更新 weaknesses、strengths、todos。
3. 所有新增记录必须有 date、question、answer、answer_type、outcome、strength、mistake、todo、evidence、status。
4. 保存 schema_version，维护 updated_at；JSON 必须通过解析校验。
5. PR/commit 前运行 JSON 解析和网页加载检查，上传到 main 后等待 Pages 部署；刷新数据即可看到新增项。
6. 不能在不存在的原始录音上伪造题干、回答、分数或来源；第三方面经永不标记为本人被问过。

四、公开发布红线
1. 这是公共网站，不要上传真实客户、面试官姓名、身份证、手机号、公司内部接口/架构机密、私钥、凭证、薪酬和私人家庭信息。
2. 所有包含敏感信息的原始逐字稿必须先脱敏；无法脱敏则只能留在私有存储，不进 public 仓库。
3. 网站是静态部署，不是即时写入服务；必须由有 GitHub 仓库写入权限的 Agent/工具提交变更。无权限时输出 JSON Patch 或待合并文件，不宣称已经同步。
