# 2012 · 单链表共同后缀与最优归并顺序

> 卷面位置：2012 年综合卷 第 41 题、第 42 题。分值以卷面为准。

## 第 42 题：两个单词链表的共同后缀

假定采用带头结点的单链表保存单词，当两个单词有相同的后缀时，可共享相同的后缀存储空间。设 str1、str2 分别指向两个单词所在单链表的头结点，结点结构为 `data | next`。设计一个时间上尽可能高效的算法，找出由 str1 和 str2 所指两个链表共同后缀的起始位置。要求：给出基本设计思想；用 C/C++/Java 描述算法并注释；说明时间复杂度。

## 考点

- 共同后缀的起点之后两链表结点完全相同（物理共享）；
- 长度不同 → 先让长的走差值步，把尾部对齐；
- 不能从头同时走，也不能比较 data 值（可能有重复字符）。

## 思路

1. 分别遍历两个链表求长度 m、n；
2. 长链表指针先走 |m-n| 步，使两指针到各自表尾的剩余结点数相同；
3. 两指针同步后移，第一个指针相同的结点即共同后缀的起始位置；
4. 若走到 NULL 仍未相遇，返回 NULL。

## 参考实现（C）

```c
typedef struct LNode {
    char data;
    struct LNode *next;
} LNode, *LinkList;

LNode *commonSuffix(LinkList str1, LinkList str2) {
    int m = 0, n = 0;
    for (LNode *p = str1->next; p; p = p->next) m++;
    for (LNode *p = str2->next; p; p = p->next) n++;

    LNode *p = str1->next, *q = str2->next;
    while (m > n) { p = p->next; m--; }
    while (n > m) { q = q->next; n--; }
    while (p && q && p != q) { p = p->next; q = q->next; }
    return p;          /* NULL 表示无共同后缀 */
}
```

## 复杂度

- 时间：O(m+n)，两趟遍历；
- 空间：O(1)。

## 容易丢分的地方

- 比较 `p->data == q->data` 就返回：两个单词中间字符相同但后缀不共享时误判；
- 指针比较用 `p->data` 而不是结点地址；
- 忘记「带头结点」，把表头也算进长度，差值错一位。

## 第 41 题：6 个有序表的最优两两合并

已知 6 个有序表 A、B、C、D、E、F，分别含 10、35、40、50、60、200 个元素，元素按升序排列。要求通过 5 次两两合并，把 6 个表最终合并成 1 个升序表，并使最坏情况下比较的总次数达到最小。请给出完整的合并过程与总比较次数，并描述 n 个不等长升序表的一般合并策略及理由。

**这就是最佳归并（哈夫曼）思想：** 每次合并的长度和记为该次比较次数的上界（最坏情况下，两个长 m、n 的表归并需要 m+n-1 次比较，按 m+n 计即长度和），于是「总比较次数」等于所有内部结点权值之和，即哈夫曼树的带权路径长度。策略就是每次取当前最短的两个表合并。

| 步骤 | 合并 | 新表长度 |
|---|---|---|
| 1 | A(10) + B(35) | 45 |
| 2 | 40 + 45 | 85 |
| 3 | 50 + 60 | 110 |
| 4 | 85 + 110 | 195 |
| 5 | 195 + 200 | 395 |

总比较次数 = 45 + 85 + 110 + 195 + 395 = **830**。

**一般结论：** n 个不等长升序表的最优两两合并 = 构造哈夫曼树，权值为表长，按「每次取最小的两个」贪心合并，最坏比较总次数等于哈夫曼树的带权路径长度。理由：越短的表被重复归并的次数越少越好，交换论证可证明贪心选择不劣于任何其他顺序。

**易错点：** 按顺序从头两两合并（10+35、45+40、85+50…）也能得出一个合法过程，但不是最优；这题问的是「最小」比较次数。
