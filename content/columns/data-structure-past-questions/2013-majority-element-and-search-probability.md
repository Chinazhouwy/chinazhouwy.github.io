# 2013 · 主元素与查找概率的排列优化

> 卷面位置：2013 年综合卷 第 41 题（13 分）、第 42 题（10 分）。

## 第 41 题（13 分）：主元素

已知一个整数序列 A = (a0, a1, …, an-1)，其中 0 ≤ ai < n（0 ≤ i < n）。若存在 ap1 = ap2 = … = apm = x 且 m > n/2（0 ≤ pk < n，1 ≤ k ≤ m），则称 x 为 A 的主元素。例如 A = (0, 5, 5, 3, 5, 7, 5, 5)，则 5 为主元素；又如 A = (0, 5, 5, 3, 5, 1, 5, 7)，则 A 中没有主元素。假设 A 中的 n 个元素保存在一个一维数组中，请设计一个尽可能高效的算法，找出 A 的主元素。若存在主元素，则输出该元素；否则输出 -1。要求：给出基本设计思想；用 C/C++ 描述算法并注释；说明时间复杂度与空间复杂度。

## 考点

- 计数排序式的哈希计数是 O(n) 时间 + O(n) 空间，只能拿及格分；
- 摩尔投票（同归于尽）能在 O(n) + O(1) 内找出「候选者」；
- 候选者必须二次验证，这是本题的分水岭。

## 思路

第一阶段（抵消）：候选 c = A[0]，计数 cnt = 1；遍历后续元素，与 c 相同则 cnt++，不同则 cnt--，cnt 归零时把当前元素设为新候选、cnt = 1。若存在主元素，它一定活到最后成为候选。

第二阶段（验证）：再扫一遍统计 c 的出现次数，若 > n/2 输出 c，否则输出 -1。

## 参考实现（C）

```c
int majority(int A[], int n) {
    int c = A[0], cnt = 1;
    for (int i = 1; i < n; i++) {
        if (A[i] == c) cnt++;
        else {
            if (cnt > 0) cnt--;
            else { c = A[i]; cnt = 1; }
        }
    }
    cnt = 0;                          /* 复用计数器做验证 */
    for (int i = 0; i < n; i++)
        if (A[i] == c) cnt++;
    return cnt > n / 2 ? c : -1;
}
```

## 复杂度

- 时间：O(n)，两趟扫描；
- 空间：O(1)。

## 容易丢分的地方

- 只做第一阶段就输出候选：没有主元素时（如 0,5,5,3,5,1,5,7）会错误地给出 5；
- cnt 归零时的处理写成 `c = A[i]; cnt = 1;` 前忘了跳过当前元素，导致重复计数；
- 用 `cnt > n/2` 写成 `>=`，n 为奇数时判定边界错。

## 第 42 题（10 分）：按查找概率重排以提高查找效率

设包含 4 个数据元素的集合 S = {do, for, repeat, while}，各元素的查找概率分别是 p1 = 0.35、p2 = 0.15、p3 = 0.15、p4 = 0.35。将 S 保存在一个长度为 4 的顺序表中，采用折半查找法，查找成功时的平均查找长度为 2.2（题面给定）。要求：

1. 若采用顺序存储结构，请给出一种使平均查找长度最短的元素排列，并求出该情况下的平均查找长度；
2. 若采用链式存储结构，且只能顺序查找，请给出一种使平均查找长度最短的元素排列，并求出该情况下的平均查找长度。

**第一问（顺序表 + 折半）：** 折半查找的比较次数只由元素在判定树中的层数决定。把查找概率最大的两个元素放在判定树的上两层（根 = 第 2 个位置，左右子树各一）。按 `do, while, for, repeat` 排列时判定树根为 while，深度分别是 while=1、do=2、for=2、repeat=3：

ASL = 0.35×1 + 0.35×2 + 0.15×2 + 0.15×3 = 0.35 + 0.70 + 0.30 + 0.45 = **1.8**

**第二问（链表 + 顺序查找）：** 链式存储只能顺序查找，最优排列就是把概率降序排列 `do, while, for, repeat`，比较次数依次为 1、2、3、4：

ASL = 0.35×1 + 0.35×2 + 0.15×3 + 0.15×4 = 0.35 + 0.70 + 0.45 + 0.60 = **2.1**

**易错点：** 以为两种结构可以用同一种排列；顺序表的折半查找要求按判定树分层放高频元素，而不是简单按概率降序排；ASL 要按「比较次数 × 概率」求和，别漏权重。
