# 考研 408 组成原理：Cache 为什么有效，局部性如何变成速度

> 【本卡片解决】Cache 不是“更快的一块内存”这么简单，它利用的是程序访问地址的规律。

## 01｜两种局部性

```text
时间局部性：刚访问过的数据，可能很快再次访问
空间局部性：访问了一个地址，附近地址可能马上被访问
```

循环里的同一个变量体现时间局部性；数组连续遍历体现空间局部性。Cache 以块为单位搬运数据，就是为了把空间局部性一次带进来。

## 02｜一次地址访问经过什么

```text
CPU 地址
  ↓ 拆成 标记 Tag / 组号 Set / 块内偏移 Offset
判断对应组中是否命中
  ├─ 命中：直接取数据
  └─ 未命中：访问下一层并装入 Cache
```

地址字段如何划分，取决于 Cache 总容量、块大小、组数和地址位数。做计算题前先统一单位：容量是字节还是字，地址是否按字节编址。

## 03｜三种映射的差异

| 映射 | 放置位置 | 冲突 | 硬件代价 |
|---|---|---|---|
| 直接映射 | 固定一组一行 | 较多 | 低 |
| 全相联 | 任意行 | 少 | 高 |
| 组相联 | 固定一组、组内任意 | 居中 | 居中 |

命中率不是唯一目标。Cache 设计要在命中率、比较器数量、访问时间和替换复杂度之间权衡。

## 04｜平均访问时间的直觉

可以把平均访问时间理解为：

`命中时间 + 未命中率 × 未命中额外代价`。

题目给多级 Cache 时，要明确每一级的命中率是局部命中率还是整体命中率，不能直接相乘或相加。

## 易错点

- 块内偏移由块大小决定，不由 Cache 总容量决定。
- 组号位数由组数决定，直接映射的组数等于行数。
- 写回和写直达讨论的是写操作一致性，不是替换策略。
- TLB 缓存的是地址翻译结果，不等于 Cache 中的数据缓存。

## 一句话结论

Cache 题的核心不是背映射名词，而是沿着“地址拆分 → 命中判断 → 缺失处理 → 平均代价”走完整条链。
