## 核心要点

### 1. 分词是 LLM 处理文本的第一道工序

- 模型无法直接吃原始文本，需要先把文本切成 **token（词元）** 再映射为 id。
- **词表（Vocabulary）**：模型认识的所有 token 集合，词表大小是模型配置的一部分（演示示例为 1024）。
- 分词结果**很大程度上决定了词表的大小**，进而影响模型参数量与训练效率。

### 2. 早期分词的困境

- 如果词表只收录常见词，遇到**词表外的生词（OOV）**就无法表示，程序会直接报错。
- 纯字符级切分又太碎、序列太长；纯词级切分又覆盖不了所有形态变化和组合词。
- 出路：**子词（subword）分词**——常用词整词入表，生词退化为子词/字符组合，兼顾覆盖率和序列长度。

### 3. BPE 算法原理（Byte Pair Encoding）

迭代式的**自底向上合并**：

1. 先把语料切成最细的**基础单元**（字符/字节），统计频率。
2. 每一轮统计相邻 token 对（pair）的出现次数，找出**最高频的 pair**。
3. 把该 pair 合并成一个新 token 加入词表。
4. 重复 2-3 步，直到满足停止条件。

> 直觉：反复合并“最常见的相邻组合”，让词表自动长出高频词/常见词缀，而不是人工枚举。

### 4. 演示中的合并过程与停止条件

- 语料去重后得到 **891 个基础字符**。
- 目标词表大小 **1000** → 每合并一次词表 +1，共需 **109 轮合并**（891 → 892 → … → 1000）。
- 视频演示了三种典型的**停止条件**：
  1. **达到目标词表大小**（演示主条件：1000）；
  2. **最高频 pair 的频率低于阈值**（例如某 pair 只出现 3 次，继续合并收益过低）；
  3. **达到最大合并次数**上限。

### 5. 实战演示

- 结尾用分词工具现场演示：同一段文本在不同词表大小 / 不同训练语料下，切分结果和 token 数差异明显。
- 观察点：合并轮数越多、词表越大，常见词越倾向整词成 token，序列长度越短；但词表过大会拖累 embedding 层与 softmax 开销。

## 补充理解（非视频原话）

- BPE 是当前主流 LLM 的事实标准分词方案（GPT 系列 tiktoken、Llama 等的底层思路），同一家族还包括 WordPiece（BERT）与 Unigram（SentencePiece）等变体，核心取舍一致：**在“词表大小”与“序列长度”之间找平衡**。
- 实际工程中 BPE 常作用于 **byte 级别**（byte-level BPE），保证任意 Unicode 文本（含 emoji、多语言）都能被无遗漏地编码。

## 为什么值得看

- 面试高频基础题：LLM 怎么把文本变成数字、词表怎么来的——BPE 是标准答案的骨架。
- 5 分钟视频用“891 → 1000”一个具体数字把合并过程讲透，比纯概念好记。
- 结尾的实战演示可以直接复现，加深对 tokenizer 行为的直觉。
